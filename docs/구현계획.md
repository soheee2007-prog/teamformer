# 팀 편성 웹 앱 구현 계획

> **에이전트 작업자용:** superpowers:subagent-driven-development 또는 superpowers:executing-plans로 과제 단위로 구현한다. 단계는 체크박스(`- [ ]`)로 추적한다.

**목표:** PRD의 팀 편성 Streamlit 앱을 만들어 Streamlit Community Cloud에 배포한다.

**구조:** 규칙은 DB와 화면을 모르는 순수 함수(`rules.py`, `roster.py`)로 모으고, `service.py`가 DB 트랜잭션 안에서 규칙을 적용해 안내 문구를 돌려준다. `ai.py`는 1, 2, 3차 모델과 스스로 배정을 이어 붙이고, `streamlit_app.py`는 화면과 key만 맡는다.

**기술:** Python 3.13, Streamlit 1.66 이상, psycopg 3 + psycopg-pool(Supabase Postgres), bcrypt, requests(OpenRouter), python-dotenv, pytest

**스펙:** [docs/PRD.md](PRD.md). 이 계획은 PRD를 근거로 하므로 둘을 함께 읽는다.

## 전역 제약

- 모든 테이블 이름은 `tf_`로 시작한다.
- 화면 key는 PRD 6절 표와 글자 하나까지 같아야 한다(영문, 숫자, 밑줄만).
- `result`의 안내는 `승인`, `대기`, `거절`, `막힘` 가운데 하나로 시작하고, 형식은 `첫 단어: 내용`이다.
- 역할 문자열 6개: `기획자`, `웹 프로그래머`, `프론트엔드 디자이너`, `테스터`, `보고서 작성자`, `발표자`
- 비밀 값 이름: `OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`. 출력하지 않는다.
- 학생 비밀번호는 `1234`, 저장은 bcrypt 해시. 관리자 학번은 `admin`
- AI 모델은 `nvidia/nemotron-3.5-super-vl:free`, `google/gemma-4-31b-it:free`, `dots-studio/dots-3-note-preview:free` 순서. 모델마다 전체 120초. `openrouter/free` 금지
- 자동 갱신 간격은 5초(`st.fragment(run_every=5)`)
- 연습 시나리오의 이름, 순서에 맞춘 특수 처리 금지(시험 코드에서만 시나리오를 쓴다)
- 새 파일 맨 위에 `생성: YYYY-MM-DD HH:MM KST` 주석을 단다. 시각은 PowerShell로 확인한다(추측 금지).
- 코드 주석, 화면, 출력 메시지는 한국어로 쓴다. 단순 열거에는 가운뎃점 대신 쉼표를 쓴다.
- 커밋과 푸시는 소희 씨가 요청할 때만 한다. 아래 "커밋" 단계는 요청을 받은 뒤 실행한다.

## 검토 초점

1. 지원한 뒤 팀에 새 팀원이 들어온 경우: 새 팀원도 투표해야 하고, 그 사람이 투표하기 전에는 승인되지 않는다. → 과제 6의 `test_new_member_must_vote`
2. AI가 JSON을 코드 블록(```json)으로 감싸거나, `team_no`를 `"1"`처럼 문자열로 주거나, 같은 학생을 두 번 넣은 경우: 앞의 둘은 해석하고, 중복은 검사에서 실패시킨다. → 과제 7의 `test_parse_variants`, 과제 3의 `test_check_duplicate_student`
3. 학번 입력에 앞뒤 공백이 있거나 CSV에 BOM, 공백이 있는 경우: 지운 뒤 처리한다. → 과제 4의 `test_bom_and_spaces`, 과제 5의 `test_login_strips_spaces`
4. 확정을 누르기 전에 DB 상태가 바뀌어 배정안이 더는 맞지 않는 경우(예: 명단을 다시 올림): 저장하지 않고 `막힘`으로 안내한다. → 과제 6의 `test_confirm_rechecks`
5. `ADMIN_PASSWORD`를 바꾼 뒤 앱을 다시 시작한 경우: 새 비밀번호로만 로그인된다. → 과제 5의 `test_ensure_admin_updates_password`
